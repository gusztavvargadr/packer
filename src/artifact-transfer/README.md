# Artifact transfer

This module owns the internal preparation and restoration used to hand image artifacts between clean Azure Pipeline jobs. Its supported representations are unpacked Vagrant box contents produced by Packer Vagrant plugin 1.1.6 and a VirtualBox native image produced from a powered-off registered VM.

The shared pipeline routes every Vagrant box through the standard artifact `image` directory and routes every VirtualBox native image and Vagrant box through the sparse-preserving provider contract. These are ordinary artifact-type and provider behaviors rather than opt-in migration modes.

`vagrant_box.rb prepare <artifact-directory>` extracts the uncompressed Packer-produced `vagrant/vagrant.box` with `bsdtar` (`tar.exe` on Windows), discovers its provider from `metadata.json`, and promotes the unpacked contents to `image` through a sibling staging directory. Hyper-V preparation removes `Virtual Machines/box.xml` and requires exactly one `.vmcx` directly under `Virtual Machines`. Every provider is repackaged without compression from the same normalized contents before the normal Vagrant boot test, and the original Packer box remains recoverable until promotion succeeds.

`vagrant_box.rb restore <artifact-directory>` repackages the downloaded `image` contents with `bsdtar` (`tar.exe` on Windows) and `pigz` into a gzip-compressed `vagrant/vagrant.box` through sibling staging and rollback. There is no single-stream gzip fallback. The helper reports component durations and input and output sizes; Packer's checksum post-processor remains the publication checksum authority.

The standalone Cake target validates and reports the installed tar and `pigz` versions before exercising the real preparation and restoration workflow. Its output records the measured archive work, exact-byte checksum result, and functional outcomes without enforcing performance thresholds.

`virtualbox_native.rb prepare-virtualbox-vagrant` converts the provisioned, powered-off VirtualBox VM to a canonical OVF, NVRAM, and monolithic-sparse VMDK inside the existing Windows or Ubuntu Packer build. The build's `artifice` boundary passes those sparse inputs directly to the pinned Vagrant post-processor before the common `vagrant_box.rb` flow. The conversion immediately asserts the canonical file set, monolithic-sparse medium, sparse OVF shape, and exact disk-attachment restoration; the normal consuming build and boot test provide package compatibility coverage.

`virtualbox_native.rb prepare-virtualbox-native` completes Packer's registered VDI or non-stream-optimized VMDK handoff inside the existing Windows or Ubuntu build. It preflights free space, stages atomically, restores the exact disk attachment on every path, removes only the Packer VM it owns, promotes the canonical OVF, NVRAM, and monolithic-sparse VMDK, and writes `virtualbox-manifest.json` with the versioned provider contract. Packer's shared manifest and checksum post-processors then record the canonical files consistently across providers. The conversion's immediate assertions cover the complete canonical file set, positive VirtualBox `VMDK`/`dynamic default` medium contract, sparse OVF declaration, restored attachment, and OVF import shape; ordinary derived-native and Vagrant builds provide downstream compatibility coverage.
